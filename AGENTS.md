## Миссия

Создать удобный агрегатор **деловых мероприятий Новосибирска**: события, календарь,
целевые аудитории, организаторы/бизнес-клубы, ожидаемая посещаемость,
контакты для партнёрств и рекламные места. UX ориентир — удобство сервисов
типа «Яндекс Афиши», **не копирование их дизайна или материалов**.
«Харизма» и «Мой бизнес» — примеры потенциальных источников/партнёров,
а не подтверждённые интеграции.

## Репозиторий и ветки

- Репозиторий: https://github.com/Alexon-Git/Afisha
- `master` — текущая **основная ветка GitHub** (default branch).
- `main` — сохранённая историческая версия; не переписывать и не удалять.
- Новую функциональность и рискованные исправления делать в отдельных
  `feature/*` или `fix/*` ветках с PR в `master`, если пользователь
  явно не поручил другой процесс.
- Никакого force-push, удаления веток, массового рефакторинга, публикации,
  деплоя или изменения реальной БД без явного разрешения.

## Правила работы и проверки

1. **Не выдумывай завершённый функционал.** Различай «реализовано»,
   «в коде, не проверено», «планируется» и «предположение».
2. До правок изучи затрагиваемые файлы и существующие тесты. Делай
   небольшие изменения с понятной причиной и возможностью отката.
3. Изменения модели данных оформляй версионированной Alembic-миграцией.
   Не возвращай `Base.metadata.create_all()` при запуске приложения,
   `ensure_columns()`, не вызывай автоматический seed событий.
4. Существующая БД без Alembic может иметь другую схему. Не запускай
   `alembic stamp`, `downgrade` или миграции на production до сверки
   схемы и проверки резервной копии; см. `backend/MIGRATIONS.md`.
5. Не коммить `.env`, токены, секреты, дампы и реальные персональные данные.
   В логах не выводи пароли/токены. Учитывай 152-ФЗ и согласия при обработке
   персональных данных; юридические детали требуют проверки.
6. При изменении API обнови Pydantic-схемы, типы frontend и тесты.
   Для публичных страниц предусмотрены стабильные URL и поисковая индексация.
7. Минимальные проверки: `cd backend && pip install -r requirements-dev.txt
   && pytest -q`; `cd frontend && npm ci && npm run build`.
   Указывай, что реально запускал, и полный результат. CI не заменяет
   проверку работы в браузере.
8. Не запускай внешние AI-скиллы и инсталляторы (`gstack` и др.)
   без проверки установочных действий и разрешения на выполнение команд.
9. По окончании задачи обнови `docs/DEVELOPMENT_CONTEXT.md` и
   `docs/AGENT_HANDOFF.md`, отметь решение в `docs/DECISIONS.md`,
   если меняется архитектура или scope.
10. При противоречии файлов ориентируйся на фактический код, CI и
    более свежие явно подтверждённые решения пользователя; сообщи о конфликте.

## Технологическая база (текущее состояние)

- Backend: Python 3.11, FastAPI, SQLAlchemy, Pydantic, Alembic.
- DB: PostgreSQL 17 для планируемого production, SQLite для локальной разработки.
- Frontend: React 18, TypeScript, Tailwind CSS, Create React App.
- Infra: Docker Compose, Nginx; готовый production-сервер не выбран.
- Переход на Next.js обсуждался **как вариант**, но не утверждён и не внедрён.

## Что не делать сейчас

- Не мигрировать frontend на Next.js «по умолчанию».
- Не создавать билеты, онлайн-оплату, CRM, networking или AI-рекомендации
  вне согласованного MVP.
- Не размещать фиктивные показатели посещаемости как реальные.
- Не объявлять монетизацию или партнёрские отношения действующими без фактов.

## Формат отчёта агента

1. **Цель и рамки**; 2. **что проверено**; 3. **что изменено** (файлы и ссылки);
4. **тесты** (фактические команды и статус); 5. **риски/неготовое**;
6. **следующее действие**. Все блокеры маркировать P0/P1/P2.
