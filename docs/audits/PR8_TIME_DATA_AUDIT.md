## Целевой контракт, пока не внедрён

API принимает только datetime с явным offset; нормализация абсолютного момента
в UTC, PostgreSQL timestamptz. Календарные границы Asia/Novosibirsk переводятся
в UTC до сравнения; `date_to` включает весь последний местный день.
Naive ввод должен отклоняться. Например, `2026-11-12T12:00:00+07:00` и
`2026-11-12T05:00:00Z` — один момент. Старому `2026-11-12 12:00:00` без
подтверждённого источника нельзя автоматически приписать ни UTC, ни +07:00.

## Отдельный черновик только для пустой events

`backend/migration_drafts/0004_event_datetime_utc.py` **не входит в Alembic
versions**, не запускается при старте приложения и не меняет рабочую схему.
Он требует PostgreSQL и online-проверку, берёт ACCESS EXCLUSIVE lock с timeout,
отказывает при любой записи events и проверяет исходный тип. Для пустой таблицы
DDL использует явный UTC, исключая зависимость от TimeZone сессии. Это не правило
интерпретации исторических данных. Downgrade запрещён до отдельного backup/export
и плана: автоматическое удаление зоны могло бы потерять смысл значений.

Нельзя просто перенести файл в versions: одновременно нужны модель хранения,
aware API, UTC-границы фильтров, SQLite-совместимость и регрессионные тесты.
