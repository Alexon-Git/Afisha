# Codex: подготовка рабочего места Afisha

**Дата:** 2026-11-12  
**Репозиторий:** https://github.com/Alexon-Git/Afisha  
**Основная ветка:** `master`. Ветка `main` — историческая.

## 1. Синхронизация локальной папки

GitHub и папка на Mac не синхронизируются автоматически. Открой терминал **внутри папки проекта**. Путь с кириллицей и пробелами нужно брать в кавычки, если вводишь его вручную. Не предполагай, что название `/партнерство/ бизнесс афиша` является абсолютным путём: сначала проверь `pwd`.

Если папка полностью пустая:

```bash
git clone --branch master https://github.com/Alexon-Git/Afisha.git .
```

Если репозиторий уже клонирован:

```bash
git status
git switch master
git pull --ff-only origin master
```

Не удаляй незакоммиченные файлы и не выполняй `git reset --hard`.

## 2. Диагностика без установки

Из корня Afisha:

```bash
bash scripts/codex-preflight.sh
```

Скрипт только читает состояние Git, доступность Git/Python/Node/npm/Codex/Bun/Docker, наличие виртуального окружения, npm-пакетов и gstack. Он не выводит секреты и не меняет файлы.

## 3. Установка зависимостей приложения (отдельное действие)

Для разработки и локальных проверок:

```bash
bash scripts/codex-bootstrap.sh --deps
```

Скрипт создаёт `backend/.venv` при необходимости, устанавливает зависимости из `backend/requirements-dev.txt` и запускает `npm ci` во frontend. Нужен интернет, подходящие версии Python, Node.js и npm.

Команда **не запускает миграции, сервер, тестовые события или деплой**. Для ознакомления Codex с кодом установка зависимостей не обязательна.

### Запуск backend — только на безопасной локальной БД

```bash
cp -n backend/env.example backend/.env
# Измени SECRET_KEY и ADMIN_PASSWORD в backend/.env на уникальные секреты
cd backend
.venv/bin/python start.py
```

**Внимание:** `start.py` применяет Alembic migrations к `DATABASE_URL`. Не используй его на существующей БД до сверки схемы и резервной копии по `backend/MIGRATIONS.md`. Файлы `.env` не коммитятся.

### Запуск frontend

```bash
cd frontend
npm start
```

На момент подготовки `frontend/src/config/api.ts` содержит жёстко заданный production origin. Для связки с локальным API требуется отдельная настройка и реальная проверка.

## 4. Установка gstack для Codex — опционально

gstack — сторонний инструмент, не часть кода Afisha. Ничего не устанавливается автоматически при чтении проекта.

Официальная инструкция: https://github.com/garrytan/gstack#other-ai-agents

Для отдельного скачивания:

```bash
bash scripts/codex-bootstrap.sh --gstack
```

Скрипт проверяет Bun, требует явного подтверждения `INSTALL`, клонирует репозиторий в `~/gstack` (не перезаписывая существующий) и **не запускает сторонний installer автоматически**.

Проверь `~/gstack/setup`. После проверки:

```bash
cd ~/gstack
./setup --host codex --no-team --no-browser
./setup --status
```

`--no-team` не включает принудительные team hooks; `--no-browser` откладывает загрузку Chromium до необходимости. Поддержка Codex в gstack может оставаться экспериментальной; сверяй актуальную документацию перед запуском.

## 5. Локальные скиллы, уже находящиеся в репозитории

При открытии рабочей папки Codex должен обнаружить проектные навыки в `.agents/skills/`:

- **`afisha-onboard`** — быстро восстановить контекст и статус задач без дорогих многоагентных запусков.
- **`afisha-p0-review`** — экономно проверить критические части FastAPI, не изменяя код.

Это собственные проектные скиллы, не gstack. Если они не появились, проверь версию Codex, доверие к рабочей папке и перезапусти сессию.

## 6. Экономный стартовый запрос

> Используй `afisha-onboard`. Прочитай `AGENTS.md` и `docs/AGENT_HANDOFF.md`, проверь состояние Git и локальной среды. Кратко объясни текущий статус проекта и предложи **одну** следующую задачу P0. Ничего не изменяй, не вызывай gstack и дополнительных агентов. После ответа остановись.

В последующих запросах загружай из `docs/` только файлы, относящиеся к конкретной задаче.

## 7. Проверки после установки

```bash
cd backend && .venv/bin/python -m pytest -q
cd ../frontend && npm run build
```

Результаты запусков должны быть записаны как **фактически выполненные**, а не предполагаемые. Предыдущий зелёный backend CI не доказывает, что локальный Mac, Docker/PostgreSQL, frontend и gstack уже проверены.

Правила веток, секретов и работы с реальной БД: `AGENTS.md` и `backend/MIGRATIONS.md`.

## Текущие ограничения

Подготовлены только исходники скриптов, инструкции и проектные скиллы. Они не были запущены на Mac пользователя. Папка на Mac должна быть отдельно синхронизирована из GitHub. Настройки личного Codex и системные пакеты пользователя не изменялись.
